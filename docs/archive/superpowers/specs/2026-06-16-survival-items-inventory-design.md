# Survival-контур, фундамент A: предметы-стеки, дроп, инвентарь

- **Дата:** 2026-06-16
- **Статус:** одобрен (готов к написанию плана реализации)
- **Sub-project:** A из дорожной карты survival (фундамент для B–F)

## Цель

Превратить чисто креативную песочницу в игру с прогрессией. Этот документ
описывает **только фундамент A**: стекаемые предметы, дроп при разрушении блока,
сбор в инвентарь, и переработку отображения инвентаря. Подсистемы B–F (крафт,
инструменты, руды/пещеры, мобы, голод) спроектированы отдельными циклами поверх A.

## Дорожная карта (контекст, не реализуется в A)

```
A. Предметы-стеки + дроп + инвентарь   ← этот spec
   └─ B. Крафт (верстак, рецепты)
         └─ C. Инструменты + прочность + скорость копания
               └─ D. Руды + пещеры + новые блоки
E. Мобы + бой   (зависит от A; можно после C)
F. Голод + еда  (зависит от A, E)
```

Каждая подсистема — отдельный spec → plan → реализация.

## Модель режимов игры

Вводится `enum GameMode { CREATIVE, SURVIVAL }`, хранится per-world в `LevelData`,
переключается командой `/gamemode <creative|survival>`.

- **Новые миры → SURVIVAL** по умолчанию.
- **Старые сейвы без поля gameMode → CREATIVE** (обратная совместимость: текущее
  поведение не ломается).

| Аспект | CREATIVE (текущее поведение) | SURVIVAL (новое) |
|---|---|---|
| Блоки | бесконечные из пикера | расходуются при установке, добываются при ломании |
| Полёт (F) | разрешён | выключен |
| Ломание | мгновенное | по `hardness` (уже реализовано) |
| Урон / падение | без урона | fall damage (уже реализовано) |
| Клавиша `E` | креатив-пикер блоков | инвентарь 36 слотов |

Флаг `instantBreak` и `flying` в SURVIVAL принудительно недоступны игроку
(остаются доступны через консольные команды как чит — не блокируем явные команды).

## Данные

### ItemStack

```
class ItemStack {
    BlockType type;   // пока «предмет = блок»; отдельные предметы (инструменты) — в C
    int count;        // 1..MAX_STACK
}
```

- `MAX_STACK = 64`.
- Пустой слот представляется `null` либо `ItemStack` с `type == AIR` —
  **выбрать одно соглашение и придерживаться его** (рекомендация: `null` = пусто,
  чтобы не путать с блоком AIR). Решение фиксируется в плане реализации.
- Класс изменяемый (mutable): `count` меняется при доливе/расходе.

### Inventory (помощник)

`Inventory` оборачивает `ItemStack[36]` (9 хотбар [0..8] + 27 основной [9..35]) и
предоставляет:

- `add(BlockType, int)` → сначала доливает в существующие неполные стеки того же
  типа, затем кладёт в первый пустой слот; возвращает остаток, который не влез.
- `removeOne(slotIndex)` → уменьшает count на 1, обнуляет слот при count==0.
- `canPlace(slotIndex)` → есть ли что ставить в выбранном слоте.
- Логику слияния/разделения курсора (см. «Взаимодействие в UI»).

### Drop-таблица

Минимальная, MC-канон. Хранится на `BlockType` (новое поле или статическая
мапа — решает план):

| Блок | Дроп |
|---|---|
| STONE | COBBLE |
| GRASS | DIRT |
| LEAVES | ничего (саженцы — позже) |
| WATER / WATER_FLOW | ничего |
| остальное | сам себя |

Количество дропа = 1 (множители — позже).

## Поведение: дроп и сбор

Реализуем **MVP: прямо в инвентарь** (без физических сущностей — система сущностей
относится к подсистеме E).

- **Ломание блока в SURVIVAL:** вычислить дроп по таблице → `inventory.add(...)`.
  Если инвентарь полон и остаток > 0 — блок всё равно ломается, лишнее теряется
  (физический дроп на землю появится позже с системой сущностей).
- **Установка блока в SURVIVAL:** взять `ItemStack` из выбранного слота хотбара →
  поставить блок → `removeOne(selectedSlot)`. При count==0 слот пустеет; если слот
  пуст — установка невозможна.
- **CREATIVE:** установка/ломание не трогают количества (бесконечно), как сейчас.

**Fast-follow (не в этом spec):** физический `DroppedItem` с гравитацией,
вращением и притягиванием к игроку — отдельной мини-сущностью, как задел под мобов.

## Отображение инвентаря (фикс)

Сейчас существуют две перекрывающиеся системы:
[`Hud.drawInventory`](../../../src/main/java/com/mineclone/game/Hud.java) (с
бесконечной палитрой «Blocks») и
[`Hud.drawCreativeMenu`](../../../src/main/java/com/mineclone/game/Hud.java)
(дублирующая сетка). Унифицируем:

| Было | Станет |
|---|---|
| `drawInventory` с палитрой «Blocks» | **Survival-инвентарь**: хотбар (9) + основной (27) + корзина + курсор, **с числами стеков** |
| `drawCreativeMenu` | **Только в CREATIVE** по `E`: пикер блоков, клик = бесконечный стек выбранного типа |

Маршрутизация клавиши `E` в `Game`:
- SURVIVAL → открыть survival-инвентарь (`drawInventory` без палитры).
- CREATIVE → открыть креатив-пикер (`drawCreativeMenu`).

### Числа стеков

- Рисуются в правом-нижнем углу слота, когда `count > 1`.
- В обоих местах: панель инвентаря (`drawInventory`) **и** хотбар на экране
  (`drawHotbar`).
- Используем существующий `TextRenderer`/`Font` с тенью для читаемости.

### Взаимодействие в UI (стеки)

- **ЛКМ по слоту:** взять весь стек на курсор / положить весь стек / при
  одинаковом типе — долить (слияние до MAX_STACK, остаток остаётся на курсоре).
- **ПКМ по слоту:** взять половину (округление вверх) / положить один предмет.
- **Корзина:** клик при непустом курсоре — очистить курсор (как сейчас).
- Курсор — это `ItemStack`, рисуется у позиции мыши с числом.

### 3D-иконки — ОТЛОЖЕНО

Иконки кубов как в MC (top + 2 боковые грани) требуют сдвинутых квадов; текущий
`UiRenderer` рисует только осевые квады (`ui.quad`, `ui.texQuad`). Оставляем
плоскую грань-иконку (как сейчас). Ключевой фикс отображения — **числа стеков**,
не 3D. 3D-иконки — потенциальная полировка в отдельном цикле.

## Сохранение

- `LevelData` хранит `ItemStack[]` (тип + count) вместо `BlockType[]`, плюс
  `GameMode`.
- `SaveFormat` — бамп версии формата; при чтении старых сейвов:
  - `BlockType[]` → конвертировать в `ItemStack[]` с `count = 1` (для не-AIR);
  - отсутствующий `gameMode` → `CREATIVE`.
- `defaultInventory()`:
  - SURVIVAL — пустой инвентарь (добываешь сам);
  - CREATIVE — текущий стартовый набор блоков (для удобства песочницы).
  - Решение, какой default подставлять, зависит от gameMode нового мира.

## Затрагиваемые файлы

**Новые:**
- `ItemStack.java`
- `Inventory.java`
- `GameMode.java` (enum; либо вложенный в подходящий класс)

**Правки:**

- `Game.java` — поле `gameMode`; place/break consume/produce; маршрут `E`;
  команда `/gamemode`; запрет полёта в SURVIVAL; стартовый инвентарь по режиму.
- `Hud.java` — `drawInventory` (числа стеков, без палитры, логика стеков ЛКМ/ПКМ);

- `LevelData.java` — `ItemStack[]` + `gameMode`, дефолты по режиму.
- `SaveFormat.java` — сериализация stacks + gameMode, бамп версии, чтение старого.
- `SaveManager.java` — если затрагивается передача данных.

## Тестирование

Тесты — `src/test/java/com/mineclone/TestMain.java` (plain main + asserts).
Добавить проверки на чистой логике (без OpenGL):

- `Inventory.add`: долив в неполный стек; переход в новый слот; переполнение
  (возврат остатка); полный инвентарь.
- `Inventory.removeOne`: обнуление слота при count==1.
- Split/merge курсора: ЛКМ/ПКМ переносы дают корректные count.
- Drop-таблица: STONE→COBBLE, GRASS→DIRT, LEAVES→пусто, прочее→само.
- Save round-trip: `LevelData` со стеками и gameMode сериализуется и читается
  без потерь; старый формат (`BlockType[]`, без gameMode) читается с дефолтами.

UI-взаимодействие (рендер) проверяется вручную запуском `.\run.ps1`.

## Вне области A (YAGNI на этот цикл)

- Физические выпадающие предметы (сущности) — fast-follow / подсистема E.
- 3D-иконки блоков в слотах.
- Крафт, инструменты, прочность, руды, мобы, голод — подсистемы B–F.
- Shift-click быстрый перенос — опционально, можно добавить, но не блокирует A.
