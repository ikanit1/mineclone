# Population behavior

1. The same seed, region state and day produce identical populations independent
   of input order. Removing four of five wolves grows rabbits by at least 50%
   within ten days in the reference forest scenario.
2. Materialization spends availability, never population; one body's death reduces
   the total once. Active and saved bodies cannot be eaten a second time by the
   abstract model.
3. Unload, save, open and return preserve reservations and mob ids. Travelling on a
   server frees the active category cap while keeping old animals in their chunks.
4. No generated animal starts in terrain, liquid, another body, a player's view or
   within 32 blocks of any living participant; groups never exceed a category cap.
5. Missing sections initialize lazily. Bad bytes are preserved before rebuilding;
   newer and oversized unknown species layouts remain opaque and disabled.
6. Ordinary time and `/ecology advance 1–60` use the same bounded daily sequence.
   Guests cannot change or inspect the authoritative ecological state via commands.
7. With the rule off, the previously recorded mob trajectory remains unchanged.
