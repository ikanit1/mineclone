# Inventory and containers

Updated: 2026-09-24. Paths in backticks are relative to the repository root.

The host owns chest/furnace contents. A guest sends gestures and expected slot
state; the host validates and sends authoritative snapshots. Network replacement
or destruction must spill contents before removing a container in both `Game`
and `DedicatedServer`. Unknown item IDs remain preserved placeholders, not air.

## Окна инвентаря (`com.mineclone.ui.container`)

Инвентарь, сундук, печь, верстак и креатив — один каркас, а не пять копий
правил. Состояние игры одно: `State.WINDOW` со своим стеком экранов. ADR:
`knowledge/decisions/inventory-windows.md`.

- **`ContainerMenu` — правила без GL и без мира.** Клик, Shift, цифра,
  протяжка, бросок, двойной клик, закрытие. Проверяются числами, а не
  кликами по живому экрану.
- **Слот описан хранилищем и ролью** (`SlotStorage` + `SlotRole`): печь
  принимает в топку только топливо, результат крафта только отдаёт. Роль
  «только забрать» решается в одном месте, а не в каждом обработчике.
- **Маршруты Shift'а задаёт экран** (`menu.route(from, to...)`): сначала
  неполные подходящие стопки целевых групп, потом пустые слоты.
- **Остаток протяжки остаётся на курсоре**, а не размазывается по слотам.
  Одна клетка — обычный клик.
- **`ContainerScreen`** — раскладка, разбор мыши и отрисовка одним пакетом:
  затемнение, стекло панели, слоты, иконки, счётчики, предпросмотр протяжки,
  перелёты, курсор на пружине, подсказка с краевым переворотом.
- **`WindowContext`** — всё, что окно знает об игре: инвентарь, режим,
  «положи игроку», «брось», щелчок, тост, настройка, раскладка клавиш.
  Поэтому окно поднимается в снимках и замерах с `PreviewContext` вместо
  половины `Game`.
- **Окно не ставит игру**: мир живёт дальше, иначе окном пережидают ночь.
- **Верстак — та же сетка, что в инвентаре** (`CraftingGrid`, 2×2 и 3×3):
  экран решает только размер и раскладку, а «что получится» считается в одном
  месте. Содержимое сетки при закрытии возвращается игроку, а не исчезает.
- `ItemIcons` — иконка предмета по форме блока: ступени — полублок и
  четверть, снег — слой 2/8, спальник — 4/8, кресты и жидкости — плоский
  тайл. Грани пишутся в буфер вызывающего без аллокаций.
- `Tooltip` / `TooltipLayout` — содержимое подсказки отдельно от места:
  своё имя янтарным, lore серым, расширенные строки (id, прочность, теги) —
  под F3+H.
- `PickBlock` — пипетка на средней кнопке; с Ctrl в креативе уносит и
  начинку блока (`BLOCK_STATE`). `DebugKeys` — F3 и сочетания: решение
  принимается на отпускании.

Формат уровня — **v11** с минимальной версией читателя и именованными
секциями; `inventory` хранит инвентарь, `pending` — курсор и отложенные стопки.
Неизвестные секции сохраняются без интерпретации. Старые версии 1–10 остаются
читаемыми. В чанке **v7** сундуки, печи и предметы лежат в отдельных секциях;
стопка хранит строковый ID и компоненты. Детали и ограничения — в [saves.md](saves.md).

Настройки (`options.dat`) — **v7**: прежние поля и привычки инвентаря дополняет
размеченный хвост настроек экрана, графики и игры. Версии 1–6 читаются с
умолчаниями для отсутствующих полей.

**Проверка всех сохранённых миров:** `java -cp "out;libs/*" tools\CheckSaves.java` —
читает `level.dat` и все чанки каждого мира, печатает `world / chunks /
stacks / missing / failures` и возвращает 1 при любом отказе. Ничего не
пишет. Текущая проверка 24.09.2026: 4 мира, 2874 чанка, 59 стопок,
ноль неизвестных предметов и отказов. Состав локальных миров меняется;
для воспроизводимой миграции используются fixtures/saves.

## Checks and tuning

`run-tests.ps1 -Only inventory,save,net` includes gesture conservation, reconnect ownership, container destruction and actual TCP transfers. `tools/ContainerBreakSmoke.java` verifies the graphical Game host as well as S_ITEMS delivery.
