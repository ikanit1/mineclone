# Меню выживания и креатива

Запрос пользователя: меню выживания и креатива не статичными сетками, а
инструментом — высокая производительность, мгновенный отклик, контент из данных
(JSON и компоненты). Дизайн согласован в разговоре по трём разделам; здесь он
записан целиком.

## Решения, принятые с пользователем

| Вопрос | Решение |
|---|---|
| Глубина контента за интерфейсом | **Честный минимум:** всё, что видно в меню, действует в игре, но набор небольшой |
| Прогрессия крафта | **Как в Minecraft:** палки, верстак, формованные рецепты, слитки из печи, уголь и алмаз — предметами |
| Мечи | Добавляются: без них «острота» и «скорость атаки» висели бы на кирке |
| Графика новых предметов | Генерируется через Higgsfield (коннектор `111`), приводится к правилам дома инструментом импорта |
| Архитектура | Реестр из JSON + компоненты стопки + общий каркас окон в пакете `ui`. Раскладка окон остаётся кодом |
| Порядок | Одна спека, четыре плана: A фундамент → B крафт и хранилища → C экипировка и статусы → D креатив |

Отвергнутые подходы: расширять enum'ы на месте (противоречит data-driven, в
сейве остаются порядковые номера, `Hud` вырос бы до 4–5 тысяч строк) и
data-driven интерфейс с раскладкой в JSON (второй UI-движок рядом с работающим
немедленным режимом меню ради раскладок, которые никто, кроме нас, не правит).

## Что есть сейчас

- `Inventory` — 36 слотов. Крафт — полка готовых рецептов без сетки
  (ADR `tools-and-crafting`). Окна инвентаря, сундука, печи и креатива нарисованы
  вручную в `Hud.java`; креатив — одна плоская сетка всех предметов.
- `ItemStack` — блок **или** инструмент **или** еда; в сейв пишутся порядковые
  номера enum'ов. Брони, левой руки, чар, зелий и данных на стопке нет.
- `UiRenderer` — **один draw call на квадрат**. Открытый инвентарь — порядка
  тысячи вызовов, обведённая цифра счётчика — ещё девять.
- Средняя кнопка мыши — отладочный перебор meta, не пипетка.
- Пакет `ui` (`MenuTheme`, `ScreenStack`, `UiInput`) — виджеты немедленного
  режима, которые водят тесты и автопилот. На нём и строятся окна.

# Часть A. Фундамент

## A1. Данные: JSON и реестр

**Парсер.** `com.mineclone.data.Json` — свой, около 300 строк: в проекте нет
системы сборки, через которую подтягивались бы зависимости. Разбирает JSON плюс
две поблажки для рукописного контента: комментарии `//` и висячие запятые —
в этом проекте комментарии пишутся везде, и данные не должны быть исключением.
Ошибка сообщает файл, строку и столбец. Обёртка `JsonObject` отдаёт поля с
умолчанием и путём в сообщении об ошибке (`items/tools.json: iron_pickaxe.tool.level`).

**Идентификаторы.** `ResourceId(namespace, path)`: `mineclone:iron_pickaxe`.
Пространство имён берётся из папки, поэтому `@mineclone` в поиске работает сразу,
а будущий мод кладёт свои данные в `assets/data/<mod>/`.

**Раскладка данных:**

```
assets/data/mineclone/
  items/        blocks.json, materials.json, tools.json, weapons.json, armor.json,
                food.json, potions.json, spawn_eggs.json, accessories.json
  tags/items/   <тег>.json
  recipes/      building.json, tools.json, armor.json, misc.json, smelting.json
  loot/         blocks.json, mobs.json
  effects.json  enchantments.json  categories.json  creative_tabs.json
```

**Предмет** — неизменяемое определение:

```json
"iron_pickaxe": {
  "name": "Железная кирка",
  "icon": "iron_pickaxe",
  "category": "tools",
  "mass": 3.0,
  "durability": 251,
  "tool": {"class": "pickaxe", "level": 3, "speed": 6.5},
  "attack": {"damage": 4, "speed": 1.2}
}
```

Поля: `name`, `icon` (имя тайла или `{"tile", "mask", "tint"}` — окраска по маске
у зелий, яиц и кожаной брони), `category`, `mass`, `max_stack` (по умолчанию 64,
у всего с износом — 1), `durability`, `hidden`, `fuel` (секунды горения), и
необязательные свойства: `block`, `tool`, `attack`, `armor`, `food`, `potion`,
`spawn`, `accessory`, `effect`, `dyeable`.

- **Блоки** остаются enum'ом — в чанке лежит байт. Каждый блок, кроме
  технических (`AIR`, `WATER_FLOW`, `DOOR_OPEN`), объявлен в `items/blocks.json`
  (`"door": {"block": "DOOR_CLOSED", "name": "Дверь", ...}`); тест требует ровно
  один предмет на каждый нетехнический блок. Физика блока (твёрдость, свет,
  требуемый инструмент) остаётся в enum, всё про предмет — в данных.
- **`ToolType` и `FoodType` удаляются.** Их строки переезжают в JSON как свойства
  предметов; порядковые номера остаются только в таблице миграции сейвов
  (`LegacyItems`) — строками, а не ссылками на удалённые enum'ы.
- **Имена русские** у всех предметов, включая блоки: сейчас блок подписан
  английским именем константы, а инструмент — русским.

**Теги.** `tags/items/<имя>.json`:

```json
{"name": "дерево", "aliases": ["wood", "древесина"],
 "values": ["mineclone:log", "mineclone:planks", "#mineclone:wooden_tools"]}
```

Часть тегов **вычисляется** из свойств и регистрируется кодом; JSON может дописать
им имя, псевдонимы и лишних участников:

| Тег | Кто входит | Псевдонимы |
|---|---|---|
| `mineclone:light` | блоки со светом > 0 | свет |
| `mineclone:durable` | всё с износом | прочность |
| `mineclone:fuel` | всё с `fuel` | топливо |
| `mineclone:food` | всё с `food` | еда |
| `mineclone:flammable` | горючие блоки | горючее |

**Категории** (`categories.json`) — порядок для сортировки и подписи:
строительные, декорации, механика, инструменты, оружие, броня, еда, зелья,
материалы, разное.

**Реестр** `ItemRegistry` загружается один раз при старте (и в тестах из того же
`assets/`). Неизвестная ссылка в данных — ошибка загрузки с путём, а не молчаливый
пропуск: сломанный JSON должен быть виден сразу, а не через час игры.

## A2. Стопка и компоненты

```java
public final class ItemStack {
    public final Item item;
    public int count;
    private ItemComponents components;   // никогда не null; пустой — общий экземпляр
}
```

**Два понятия, а не одно.** Свойства определения (класс инструмента, очки брони)
живут в `Item` и не меняются. **Компоненты** — данные экземпляра, аналог NBT и
ECS на уровне предмета. Смешивать их в одну карту, как в MC 1.20.5, гибче, но
читается хуже: «чем инструмент является» и «что с ним сделали» — разные вопросы.

| Компонент | Тип | Что делает |
|---|---|---|
| `damage` | int | износ |
| `unbreakable` | bool | износ не тратится |
| `enchantments` | карта чара → уровень | см. C4 |
| `attributes` | список (атрибут, прибавка) | урон, скорость атаки, здоровье |
| `dyed_color` | RGB | цвет кожаной брони |
| `custom_name` | строка | имя в подсказке |
| `lore` | до 4 строк | строки в подсказке |
| `effect` | эффект, уровень, длительность | переопределяет эффект зелья или амулета |
| `bag_contents` | 9 стопок | содержимое рюкзака |
| `block_state` | meta + содержимое сундука/печи | копия блока по Ctrl+пипетке |

- **Компоненты неизменяемы**, стопка меняет ссылку (`stack.with(DYED_COLOR, c)`).
  Общий пустой экземпляр не аллоцируется на каждую стопку.
- **Стопки сливаются, только если совпадают предмет и компоненты.** Иначе
  слияние молча уничтожает чары или содержимое рюкзака.
- **Тип компонента — `ComponentType<T>`**: id, двоичный кодек, равенство, копия,
  и редактор для вкладки «Редактор» (D4). Новый компонент — это один новый тип,
  а не правки в пяти местах.
- **Неизвестный компонент** при чтении хранится байтами (`RawComponent`) и
  записывается обратно как есть.
- **Неизвестный предмет** не теряется: реестр отдаёт заглушку `Item.missing(id)` —
  шахматная иконка, имя `?mineclone:ruby`, — и при сохранении пишется исходный id.
  Это та же мысль, что в ADR про сундуки: худшая потеря данных — молчаливая.

`Inventory` вместо `add(BlockType)` / `addFood` получает `add(ItemStack)` и
`canAdd(ItemStack)`. Для кэшей появляется `contentHash()` — дешёвый хэш по
36 слотам без аллокаций. Хэш, а не счётчик версий: код правит `stack.count`
напрямую, и забытое увеличение счётчика дало бы устаревший кэш, который никто
не заметит.

## A3. Сохранения

**Формат стопки (общий для игрока, сундуков, печей и предметов на земле):**

```
UTF     id              ("" — пустой слот)
VarInt  count
VarInt  число компонентов
  UTF     id компонента
  VarInt  длина
  bytes   данные
```

Id строкой, а не номером: у предметов из данных нет стабильного порядкового
номера. GZIP поверх сохранения сжимает повторяющиеся строки.

| Файл | Версия | Что добавилось |
|---|---|---|
| `level.dat` | 10 | стопки в новом формате; экипировка (4 брони, левая рука, аксессуары парами «id слота — стопка»); активные эффекты; правила мира (ход времени, режим погоды, спавн мобов); «висящие» предметы |
| чанк | 6 | сундуки, печи, предметы на земле в новом формате стопки |
| `options.dat` | 6 | расширенные подсказки, книга рецептов открыта / фильтр / категория, режим сортировки |
| `creative.dat` | 1, новый | пресеты хотбара (9 × 9 стопок) и избранное — глобально, рядом с `options.dat`, как `hotbar.nbt` в MC |

- **Висящие предметы.** Автосохранение идёт и при открытом окне (мир не стоит).
  Стопка на курсоре и содержимое сетки крафта в этот момент не лежат ни в одном
  хранилище — и пропали бы при падении игры. Снимок пишет их отдельным списком,
  загрузка возвращает их в инвентарь, а что не влезло — к ногам игрока.
- **Старые версии** (`level.dat` 1–9, чанк 1–5) читаются прежним кодом чтения
  стопки и переводятся через `LegacyItems`: блок — по ordinal в `BlockType`,
  инструменты и еда — по таблице строк в старом порядке. Износ инструмента
  становится компонентом `damage`.
- **`creative.dat`** пишется атомарно (временный файл и перенос) при закрытии
  окна креатива. Путь уважает `-Dmineclone.savesDir`, иначе автопилот портил бы
  настоящий файл.

## A4. Пакетный рендер интерфейса

`UiRenderer` перестаёт рисовать квадрат вызовом.

- **Одна динамическая VBO** и общий индексный буфер; вершина — позиция, uv,
  цвет RGBA, режим. Квадрат — четыре вершины: `quad4`/`texQuad4` ложатся на неё
  без перевода.
- **Режимы в одной программе `UI_BATCH`:** заливка; тайл атласа (блок 0); стекло —
  размытый кадр по `gl_FragCoord` (блок 1); глиф крупного шрифта (блок 2); глиф
  мелкого (блок 3); произвольная текстура (блок 4 — превью миров в меню).
  Атлас, шрифты и стекло привязаны постоянно, поэтому окно целиком — один draw
  call. Пакет сбрасывается только при смене произвольной текстуры, ножниц,
  переполнении и перед 3D-превью.
- **API не меняется:** `quad`, `texQuad`, `quad4`, `texQuad4`, `glass`,
  `begin`/`end`. `TextRenderer.draw` и `drawOutlined` кладут глифы в пакет, если
  он открыт, а вне пакета открывают его сами на одну строку. `Hud` и экраны
  меню ускоряются без правок; `MenuTheme` продолжает откладывать текст до
  границы слоя — это нужно для перекрытия диалогом, а не для скорости.
- **Трансформация** (масштаб и сдвиг) применяется к вершинам на CPU — на ней
  едет пружинное появление окна.
- **`GL_TEXTURE_2D_ARRAY` не нужен:** все тайлы уже в одном атласе, и массив дал
  бы тот же один draw call ценой второй копии атласа в памяти.
- **Счётчик draw call'ов** `UiRenderer` за кадр; в F3 строка `UI: N draw calls`.

**Иконки предметов** (`ItemIcons`, общие для окон, хотбара и подсказок):

- Блок рисуется проекцией своей **формы**, а не всегда кубом: ступени — два
  бокса, слои и спальник — плоский бокс по meta. Кресты, вода и предметы —
  плоским спрайтом, как сейчас.
- Окраска по маске (`icon.mask` + `tint`): зелья цветом эффекта, яйца двумя
  цветами, кожаная броня — `dyed_color`.
- Чары дают бегущий блик по иконке.
- Полоска прочности — как сейчас.
- `Hud.isoCubeFaces` аллоцирует массивы на каждую иконку каждый кадр. Грани
  считаются в переиспользуемый буфер.

## A5. Каркас окон

**Логика без GL** — пакет `com.mineclone.ui.container`, проверяется обычными тестами:

- `SlotStorage` — хранилище: `get`, `set`, `size`, `canPlace(i, stack)`,
  `maxCount(i, stack)`, `canTake(i)`, `onTake(i, stack)`, `changed()`. Фильтры
  (броня только в свой слот, выход печи только отдаёт, результат крафта списывает
  сетку) — здесь, а не в экране.
- `SlotGroup` — группа слотов хранилища с ролью: `HOTBAR`, `MAIN`, `BAG`,
  `ARMOR`, `OFFHAND`, `ACCESSORY`, `CONTAINER`, `CRAFT_GRID`, `CRAFT_RESULT`,
  `FURNACE_*`, `CREATIVE_SOURCE`, `EDITOR`.
- `ContainerMenu` — группы, курсор и все операции (A6). Возвращает, что выкинуть
  в мир, и где что откуда куда перелетело — для анимации.

**Экраны** — немедленный режим поверх `MenuTheme` и `UiInput`, как меню:
`InventoryScreen` (выживание и верстак — один макет, B2), `ChestScreen`,
`FurnaceScreen`, `CreativeScreen` (часть D).

**Игра.** Состояния `CREATIVE_MENU`, `CHEST_MENU`, `FURNACE_MENU` сливаются в одно
`WINDOW`. Открытое окно живёт во втором `ScreenStack` (`windows`), отдельно от
меню: у окна свой Esc (закрыть окно), а пауза поверх окна не нужна. Мир живёт
дальше, игрок стоит — как сейчас. Экраны не видят `Game`: им передаётся
`WindowContext` (игрок, инвентарь, режим, выбросить стопку, звук, тост) — в
тестах его подменяет заглушка.

`UiInput` расширяется правой и средней кнопками (нажата / зажата / отпущена) и
модификаторами. Двойной клик считает тема, как сейчас для строк списка.

## A6. Взаимодействия

**Клики в окнах:**

| Действие | Поведение |
|---|---|
| ЛКМ / ПКМ | как сейчас: взять / положить / обменять, половина / по одному — с учётом фильтров и компонентов |
| Shift+ЛКМ | перенос в «соседнее» хранилище по таблице ниже; броня — сразу в свой слот; из результата крафта — собрать максимум |
| Зажатая ЛКМ, провести по слотам | стопка курсора делится поровну по пройденным подходящим слотам, остаток остаётся на курсоре; во время протяжки видны будущие числа |
| Зажатая ПКМ, провести | по одному в каждый пройденный слот |
| Протяжка по одному слоту | обычный клик при отпускании |

Раскладка протяжек — как в MC. В исходном запросе поровну делила ПКМ; в
согласованной таблице раздела 2 и здесь — ЛКМ, потому что у игроков MC это в
руках: ЛКМ-протяжка «поровну», ПКМ-протяжка «по одному». Обе операции есть.
| Двойной клик | собрать на курсор одинаковые стопки из всех групп, кроме результата крафта, до предела стопки |
| 1–9 над слотом | обмен со слотом хотбара (клавиши — действия `SLOT_1..9`, переназначаемые) |
| Q / Ctrl+Q над слотом | выбросить один / всю стопку |
| Клик мимо окна со стопкой на курсоре | ЛКМ — выбросить всю, ПКМ — одну |

**Куда уходит Shift+клик:**

| Окно | Откуда | Куда, по порядку |
|---|---|---|
| Инвентарь / верстак | броня, амулет, рюкзак | свой слот экипировки, если пуст |
| | хотбар | основной инвентарь → рюкзак |
| | основной / рюкзак | хотбар |
| | результат крафта | хотбар → основной → рюкзак |
| | сетка крафта | основной → хотбар → рюкзак |
| Сундук | игрок | сундук |
| | сундук | основной → хотбар → рюкзак |
| Печь | игрок | топливо — в топку, переплавляемое — во вход |
| | печь | основной → хотбар → рюкзак |

Везде сначала доливаются подходящие неполные стопки, потом пустые слоты.

**В мире:**

- **Пипетка — средняя кнопка по блоку.**
  - Выживание: найти предмет блока в инвентаре; в хотбаре — выбрать слот,
    иначе обменять с выбранным слотом. Нет в инвентаре — ничего.
  - Креатив: есть в хотбаре — выбрать; иначе полная стопка в выбранный пустой
    слот, первый пустой слот хотбара или вместо выбранного.
  - **Ctrl+пипетка** (креатив) — стопка с компонентом `block_state`: meta
    (высота слоя, спальник), содержимое сундука, состояние печи. Постановка такого
    предмета восстанавливает блок целиком. В подсказке — строка «+данные блока».
- **Отладочный перебор meta** переезжает со средней кнопки на F3+средняя кнопка.
- **F3-сочетания как в MC:** F3 переключает отладку при **отпускании** и только
  если, пока он был зажат, не сработало сочетание. F3+H — расширенные подсказки
  (тост «Расширенные подсказки: вкл»), запоминаются в `options.dat`.
- **Поменять руки** — новое действие `SWAP_HANDS`, по умолчанию X (F занята
  полётом); переназначается. Раскладка хранится по имени действия, так что
  старый `options.dat` подхватывает новое действие с умолчанием.
- Q в мире остаётся заряжаемым броском.

## A7. Анимации и подсказки

- **Окно появляется пружиной:** масштаб 0,96 → 1 с лёгким перелётом (затухание
  ~0,6) и фейд ~0,12 с. Закрытие — фейд без перелёта: уходящее окно не должно
  привлекать внимание.
- **Предмет на курсоре** догоняет мышь пружиной (чуть отстаёт, увеличен на 8 %).
- **Укладка в слот:** иконка «прилипает» к центру ячейки, ячейка коротко
  пружинит масштабом 0,85 → 1.
- **Перелёты.** Shift-перенос, Quick Stack, сортировка, автовыкладка рецепта:
  иконки летят из слота в слот ~0,18 с. Логика применяется сразу; в слоте
  назначения иконка скрыта до прилёта — иначе предмет появляется дважды.
- **Подсказка** (`TooltipLayout`, чистая функция): мерит свой размер и выбирает
  угол привязки к слоту в порядке справа-снизу → слева-снизу → справа-сверху →
  слева-сверху, затем зажимается в экран с полем 4 px. Смена угла — пружиной
  позиции, а не скачком.
- **Содержимое подсказки:** имя (своё имя — янтарным); чары; атрибуты (плюс
  зелёным, минус красным); эффект цветом эффекта; lore серым; «Неразрушимый»;
  содержимое рюкзака девятью мини-иконками. **Расширенные** (F3+H) добавляют id,
  прочность числом `245/251`, теги (до шести и «…»), число компонентов.

## A8. Перенос существующих окон

План A заканчивается **паритетом**: инвентарь, сундук, печь и креатив работают
через каркас и пакетный рендер, ничего не потеряв, плюс общие взаимодействия A6.
`Hud.drawInventory`, `drawChest`, `drawFurnace`, `drawCreativeMenu` удаляются.
`ItemRenderer` (предметы на земле) и `HeldItemRenderer` (рука) переходят на
реестр: иконка, форма блока, окраска.

До подмены рендера `RenderHudPreview` снимает все кадры **старым** рендером;
после — сравнивает попиксельно. Допуск — разница сглаживания; сдвиг, пропавший
элемент или другой цвет — провал.

# Часть B. Крафт и хранилища

## B1. Материалы, верстак, добыча

- **Новые предметы:** палка, уголь, алмаз, железный и золотой слитки, кожа.
- **Новый блок `CRAFTING_TABLE`** — в конец `BlockType`. Верх — сетка, бока —
  инструменты, низ — доски; грани процедурные (им нужен стык в стиле досок).
  Твёрдость 2,5, копается топором, дроп — сам. ПКМ открывает окно инвентаря с
  сеткой 3×3.
- **Добыча из данных** (`loot/blocks.json`, `loot/mobs.json`) вместо
  `BlockType.getDrop` и `MobType.drop`:
  - угольная руда → уголь, алмазная → алмаз;
  - железная и золотая руда — сами собой, плавятся в слитки;
  - корова → сырая говядина 1–3 и кожа 0–2; остальные — как сейчас.
- **Старые сейвы не застревают:** угольная и алмазная руда в инвентаре
  переплавляются в уголь и алмаз, как в MC.
- **Переплавка и топливо из данных** (`recipes/smelting.json`, поле `fuel`):
  руды → слитки / уголь / алмаз, песок → стекло, булыжник → камень, сырое мясо →
  жареное. Топливо: уголь и угольная руда — 8 переплавок, бревно 1,5, доски и
  ступени 1, палка 0,5, верстак и сундук 1,5. Инструменты по-прежнему не горят
  (решение ADR `furnace-and-smelting`).

## B2. Сетка 2×2 / 3×3

- **Один макет.** Под сетку всегда зарезервировано место 3×3. В инвентаре
  активны четыре ячейки по центру области (сдвинуты на полячейки), на верстаке —
  все девять. Остальное окно не двигается.
- **Результат** пересчитывается при изменении сетки (по хэшу). Взять —
  списать по одному из каждой непустой ячейки; Shift — повторять, пока рецепт тот
  же и результату есть место.
- **Закрытие окна** возвращает сетку в инвентарь, что не влезло — к ногам.

**Формат рецептов:**

```json
"iron_pickaxe": {
  "type": "shaped",
  "pattern": ["XXX", " # ", " # "],
  "key": {"X": "mineclone:iron_ingot", "#": "mineclone:stick"},
  "result": {"item": "mineclone:iron_pickaxe"},
  "book": "tools"
},
"planks": {
  "type": "shapeless",
  "ingredients": ["#mineclone:logs"],
  "result": {"item": "mineclone:planks", "count": 4},
  "book": "building"
}
```

- **Сопоставление формованного:** непустое содержимое сетки обрезается до
  габарита и сравнивается с узором и его зеркалом по горизонтали — рецепт
  собирается в любом месте сетки.
- **Бесформенный:** сопоставление мультимножеств с тегами перебором с возвратом
  (не больше девяти ингредиентов).
- **«Нужен верстак»** — узор шире или выше двух, или больше четырёх ингредиентов.

**Рецепты (формы MC):**

| Результат | Узор | Ключ |
|---|---|---|
| 4 доски | бесформенный | бревно |
| 4 палки | `#` / `#` | доски |
| Верстак | `##` / `##` | доски |
| Сундук | `###` / `# #` / `###` | доски |
| Печь | `###` / `# #` / `###` | булыжник |
| 4 факела | `C` / `#` | уголь, палка |
| 4 ступени | `#  ` / `## ` / `###` | доски |
| 3 двери | `##` × 3 | доски |
| Спальник | `LLL` / `###` | листва, доски |
| Кирка ×4 | `XXX` / ` # ` / ` # ` | X = доски / булыжник / железный слиток / алмаз |
| Топор ×4 | `XX` / `X#` / ` #` | то же |
| Лопата ×4 | `X` / `#` / `#` | то же |
| Меч ×4 | `X` / `X` / `#` | то же |
| Шлем ×3 | `XXX` / `X X` | X = кожа / железный слиток / алмаз |
| Нагрудник ×3 | `X X` / `XXX` / `XXX` | то же |
| Поножи ×3 | `XXX` / `X X` / `X X` | то же |
| Ботинки ×3 | `X X` / `X X` | то же |
| Рюкзак | `LLL` / `LCL` / `LLL` | кожа, сундук |
| Амулет | ` G ` / `G G` / ` D ` | золотой слиток, алмаз |

## B3. Книга рецептов

Панель слева от окна; открыта ли, фильтр и категория запоминаются в `options.dat`.

- **Поиск** по имени и id результата **и ингредиентов** (теги раскрываются в
  имена участников): «слиток» находит всё, что делается из слитков. Сравнение
  без регистра, «ё» = «е».
- **Фильтр** «Только доступные»; **категории** — Все / Инструменты / Броня / Блоки / Разное.
- **Доступность** считается по содержимому инвентаря и сетки, пересчёт — при
  смене `contentHash`, а не каждый кадр:
  - зелёная рамка — можно собрать сейчас;
  - янтарная с бейджем «−1» / «−2» — не хватает одной-двух единиц;
  - тусклая — больше;
  - замок «нужен верстак» — рецепт 3×3 в окне инвентаря.
- **Порядок:** доступные, потом «почти», потом прочие; внутри — порядок файла.
- **Клик по рецепту:**
  1. Сетка возвращается в инвентарь (не влезает — отказ с тостом, ничего не двигается).
  2. Доступные ингредиенты раскладываются по узору на одну сборку, **Shift** — на
     максимум (по минимуму запасов и пределу стопки). Из тега берётся тот
     предмет, которого больше.
  3. Недостающие показываются в своих ячейках полупрозрачными силуэтами; силуэт
     гаснет, когда ячейку заполнили.
  4. Иконки летят из инвентаря в сетку (A7).
- **Подсказка рецепта:** результат и ингредиенты «есть / нужно» с подсветкой нехватки.

## B4. Quick Stack и сортировка

- **«Сложить в сундук»** (кнопка у сундука): каждая стопка основного инвентаря и
  рюкзака, **такой предмет которой уже лежит в сундуке**, уходит туда — сначала в
  неполные подходящие стопки, потом в пустые слоты. Хотбар не участвует: там
  держат то, что нужно в руках.
- **Сортировка** (кнопка у сундука и у инвентаря игрока). ЛКМ — сортировать,
  ПКМ — сменить режим; режим общий и хранится в `options.dat`.
  - Сначала сливаются неполные одинаковые стопки, затем стопки сжимаются к началу
    и упорядочиваются.
  - **Категория** — порядок `categories.json`, внутри по названию;
    **название** — по алфавиту (русский `Collator`); **масса** — по убыванию
    `count × mass`, при равенстве по названию.
  - У игрока сортируется только основной инвентарь (27 слотов).
- Обе операции анимируются перелётами.

## C1. Предметы

| Группа | Состав |

Базовый урон инструментов и руки согласуется с тем, как сейчас считается удар
(`HAND_DAMAGE`, бонус инструмента) — в плане C, по коду, без смены ощущения от
боя рукой.

## C2. Экипировка и руки

- **`Equipment`** у игрока: голова, грудь, ноги, ступни, левая рука и слоты
  аксессуаров. При смерти экипировка ведёт себя так же, как инвентарь сейчас.
- **Слоты аксессуаров расширяемые — из данных.** `equipment_slots.json` описывает
  каждый слот: id, какой тип аксессуара принимает, силуэт пустого слота. По
  умолчанию два: «Сумка» (только сумки) и «Амулет» (только амулеты). Новый слот —
  строка данных; окно раскладывает колонку по их числу, а сейв хранит аксессуары
  **по id слота**, поэтому добавленный или убранный слот не сдвигает чужие
  предметы. Предмет из убранного слота возвращается в инвентарь при загрузке.
- **Левая рука.** ПКМ сначала пробует основную руку (поставить блок, съесть,
  выпить, призвать); если ей делать нечего — левую. Факел в левой руке светит
  (точечный свет берёт максимум из двух рук). Предмет в левой руке виден от
  первого лица (зеркальная поза `armPose`/`itemPose`) и на модели.
- **Рюкзак.** Надетый — ряд «Рюкзак» в окне. Подобранное кладётся в рюкзак,
  когда основной инвентарь полон. Содержимое — компонент `bag_contents`, поэтому
  снятый рюкзак, рюкзак в сундуке и выброшенный рюкзак ничего не теряют. Рюкзак в
  рюкзак не кладётся (фильтр слота).

## C3. Урон и броня

Один расчёт `DamageModel` (чистая функция) вместо разбросанных `takeDamage`:

| Источник | Очки брони | Защита (чары) | Огнестойкость |
|---|---|---|---|
| удар моба | да | да | — |
| падение, огонь, горение, яд, заморозка | — | да | огонь и горение → 0 |
| голод | — | — | — |

- Очки брони: −4 % за очко, максимум 20 очков = 80 %.
- Защита: −4 % за уровень по сумме надетого, предел 20 уровней = 80 %; поверх брони.
- Удар моба изнашивает каждый надетый предмет на `max(1, урон / 4)`.

## C4. Эффекты, чары, атрибуты

**Эффекты** (`StatusEffects` у игрока; метаданные в `effects.json`, поведение в коде):

| Эффект | Действие |
|---|---|
| Регенерация | +1 HP раз в `2,5 / уровень` с |
| Скорость | +20 % скорости за уровень |
| Огнестойкость | огонь, лава и горение не ранят |
| Яд | −1 HP раз в `1,25 / уровень` с, не ниже 1 HP |
| Заморозка | скорость × 0,62, иней по краям экрана; без урона |
| Горение | −1 HP/с вне контакта с огнём; гасится водой и дождём под открытым небом; огонь и лава зажигают на 4 с сверх контакта |

- Слияние как в MC: больший уровень заменяет; при равном — более длинный.
- Накопитель тика не сбрасывается при обновлении эффекта, иначе амулет
  регенерации, обновляемый раз в секунду, никогда бы не лечил.
- **Один источник правды:** таймеры яда и заморозки в `AdvancedFeedback` и
  морозный иней (`Frost`) становятся производными от эффектов. Элитные мобы
  VENOMOUS / FROST / BURNING накладывают эффекты. Оглушение и адаптация
  экспозиции остаются в `AdvancedFeedback`.
- **Показ:** значки с таймером справа сверху в игре (мигают последние 10 с;
  у амулета — без таймера) и плашки в окне инвентаря. Сохраняются в `level.dat`.

**Чары** (`enchantments.json` — имя, максимальный уровень, к чему применимы;
формулы в коде). Уровни 1–10:

| Чары | Формула |
|---|---|
| Эффективность | скорость копания подходящим инструментом + уровень² + 1 |
| Прочность | шанс не потратить износ `уровень / (уровень + 1)` |
| Острота | урон + 0,5 × уровень + 0,5 |
| Защита | см. C3 |
| Огненный аспект | поджигает моба на 4 × уровень с |
| Добыча | к каждой строке дропа моба + случайно 0…уровень |

**Атрибуты:** урон (прибавка к удару), скорость атаки (перезарядка удара
делится на неё), здоровье (прибавка к максимуму, пока предмет надет или в руке
там, где ему место; сердца уходят во второй ряд; при снятии здоровье
обрезается по новому максимуму). `unbreakable` отключает износ.

## C5. 3D-превью и модель

- **`PlayerPreview`**: пакет интерфейса сбрасывается; `PlayerRenderer` рисует
  модель в прямоугольнике превью — свой вьюпорт и ножницы, очистка глубины,
  перспектива с полем зрения 30°, аварийный путь самотонемапа шейдера
  (`uLinearOut = 0`), без карты теней, постоянный «студийный» свет. Затем пакет
  продолжается.
- **Поворот:** перетаскивание ЛКМ по превью; голова смотрит на курсор, как в MC.
- **Броня** — второй слой боксов на 8–15 % больше частей тела, текстуры
  процедурные (`PixelArt`, раскладка скина мобов), кожаная окрашена `dyed_color`.
- **Предметы в обеих руках** — через `ItemRenderer` (блок кубиком, предмет пластиной).
- **Статусы:** горение — языки пламени горящих мобов; заморозка — ледяной
  оттенок и белый ободок; яд — зелёная пульсация и пузырьки поверх превью.
- Та же модель с бронёй, предметами и статусами — в виде от третьего лица (F5).

# Часть D. Креатив

## D1. Окно и вкладки

- **Вкладки из `creative_tabs.json`:**
  Строительные блоки, Декорации, Механика, Инструменты и броня, Зелья и эффекты,
  Спавн сущностей, Избранное. Состав — список id и `#тегов`. Вкладка без
  предметов не показывается. Тест: каждый нескрытый предмет лежит хотя бы в одной
  вкладке. «Механика», а не «Механика/Логика»: логических блоков в игре нет
  (см. «Что НЕ делается»), а пустая половина названия обещала бы их.
- **Служебные вкладки** (код): Поиск, Инвентарь, Редактор, Мир.
- **Сетка** 10 × 5 видимых ячеек с прокруткой (`ScrollState`); рисуются только
  видимые ряды.
- **Хотбар и корзина** видны на всех вкладках.
- **Правила сетки:**
  - ЛКМ по предмету — один на курсор, повторный ЛКМ тем же — ещё один;
  - средняя кнопка — полная стопка на курсор;
  - Shift+ЛКМ — полная стопка сразу в хотбар (долить, пустой слот, иначе выбранный);
  - стопка с курсора, брошенная на сетку или в корзину, удаляется;
  - **Delete+клик** по любому слоту окна удаляет стопку.
- **Вкладка «Инвентарь»:** экипировка с превью, основной инвентарь, хотбар — без крафта.

## D2. Поиск

- Поле получает фокус при переходе на вкладку «Поиск». Буква, набранная на
  другой вкладке с предметами, переключает в поиск и начинает запрос с неё.
  Клавиши-команды (E, Q, F, цифры) буквами не считаются.
- Пока поле в фокусе, клавиши печатают, а не командуют; Esc закрывает окно.
- **Запрос** — слова через пробел, все условия должны выполниться:
  - `слово` — подстрока русского имени или пути id (без регистра, «ё» = «е»);
  - `#тег` — начало id, имени или псевдонима тега (`#свет`, `#дерево`, `#прочн`);
  - `@ns` — пространство имён (`@mineclone`).
- Результат пересчитывается при изменении запроса; пустой запрос — все предметы.

## D3. Избранное и пресеты хотбара

- **Избранное:** F над предметом в любой сетке окна креатива — добавить / убрать.
  Хранится стопка вместе с компонентами (отредактированные предметы тоже).
  Звёздочка на иконках избранного. Глобально, в `creative.dat`.
- **Пресеты:** панель справа — девять мини-хотбаров.
  - **Shift+N** — сохранить текущий хотбар в пресет N, **Ctrl+N** — загрузить,
    клик по ряду — загрузить; тост в обоих случаях.
  - Сочетания работают **только в окне креатива** и не в фокусе поля поиска.
    В игре Shift — спуск, Ctrl — бег: Ctrl+1 на бегу молча затирал бы хотбар,
    а Shift+1 при спуске — пресет.
  - Глобально, в `creative.dat`.

## D4. Редактор предмета

- **Слот «Предмет»** — рабочий слот окна; при закрытии возвращается в инвентарь.
- **Живая подсказка** над формой — ровно та, что увидит игрок.
- **Форма** показывает только применимое; каждое поле — редактор своего
  `ComponentType`:

| Секция | Поля | Когда видна |
|---|---|---|
| Общее | имя (до 40 символов), lore (до 4 строк), количество (1…предел стопки) | всегда |
| Прочность | неразрушимый, износ (0…прочность−1) | предмет с износом |
| Чары | применимые чары, степпер 0…10 | есть применимые |
| Атрибуты | урон −5…+20 (шаг 0,5), скорость атаки −2…+4 (0,1), здоровье 0…+20 (1) | всегда |
| Цвет | 16 образцов и RGB-ползунки | `dyeable` |
| Эффект | эффект, уровень 1…5, длительность 5 с…10 мин | зелья и амулеты |

- **Кнопки:** «Взять копию» (на курсор), «В избранное», «Сбросить» (убрать все компоненты).
- Форма прокручивается, если не помещается.

## D5. Вкладка «Мир»

| Контрол | Действие |
|---|---|
| Ползунок времени 00:00–24:00 | время внутри текущих суток — той же функцией, что `/time set` (номер суток и фаза луны сохраняются); после — `invalidateShadows()` |
| Рассвет / Полдень / Закат / Полночь | 06:00 / 12:00 / 18:00 / 00:00 |
| Остановить время | правило «ход времени» |
| Погода: Цикл / Ясно / Дождь / Гроза | режим погоды; не «Цикл» — погода заморожена в этом виде (`Weather` получает переопределение вида, осадки по-прежнему решает биом) |
| Спавн мобов | правило; уже живущие мобы остаются |
| Полёт | `player.flying` |
| Очистить предметы (N) | убрать все предметы на земле; N обновляется вживую |

Правила сохраняются в `level.dat` v10. Вкладка есть только в креативе.

Процедурно: грани верстака (стык в стиле досок) и текстуры брони на модели
(точная UV-раскладка).

## Конвейер

1. **Higgsfield** (коннектор `111`) генерирует листы 4×4 по общему стилевому
   промпту: пиксель-арт иконки инвентаря, свет сверху-слева, тёмный контур,
   ограниченная палитра, ровный фон-хромакей, без текста и теней. Модель
   выбирается пробным листом на старте работ над графикой.
2. **`tools/ImportGeneratedIcons.java`** — детерминированная доводка:
   - нарезка листа, хромакей → **бинарная** альфа, удаление мусорных пятен;
   - обрезка по габариту и уменьшение до **мастера 16×16** выбором
     преобладающего цвета (73 из 89 существующих спрайтов — 16×16; движок
     удваивает);
   - квантование в **5-ступенчатые рампы со сдвигом оттенка** и **байеровский
     дизеринг 4×4** — правила `GenBlockTextures`;
   - однопиксельный контур тёмной ступенью рампы;
   - запись в `assets/textures/blocks/<имя>.png` — только если файла нет, либо
     с `--force` (правило генератора: рукописное не затирается);
   - контрольный лист `out-test/previews/icons-contact.png` ×8 с подписями.
3. **Заглушки первыми.** Для каждого нового тайла `GenBlockTextures` сначала
   создаёт процедурную версию, поэтому пурпурной шахматки в игре не будет, даже
   если коннектор недоступен. Сгенерированный спрайт заменяет заглушку.
4. **Просмотр** — кадры `RenderHudPreview` с новыми иконками, а не только PNG.

Атлас вмещает 256 тайлов; занято ~89, прибавится ~55.

# Производительность

- **Draw call'ы интерфейса:** открытый инвентарь — не больше 3 без 3D-превью
  (сейчас ~1000), креатив — не больше 4.
- **`tools/BenchUi.java`** рядом с `BenchShaders` и `BenchPathfinder`: инвентарь,
  сундук, креатив с полной сеткой; draw call'ы и мс на кадр с `glFinish`, первый
  прогон выбрасывается. Замер **до** начала плана A и после каждой части; цифры —
  в ADR.
- **Кэши:** доступность рецептов — по `contentHash`; поиск — по изменению
  запроса; сетка креатива — только видимые ряды; грани иконок без аллокаций.

## Сейвы на живых данных

`tools/CheckSaves.java` — **только чтение**: открывает все миры в `saves/`
(сейчас 13), читает `level.dat` и все чанки через новый загрузчик, печатает
число стопок и заглушек `missing`, падает на любом отказе. Миры пользователя не
перезаписываются.

## Снимки (`RenderHudPreview`)

Попиксельное сравнение старых кадров со старым рендером (A8), затем новые кадры:
инвентарь с книгой (все состояния рамок, силуэты рецепта), верстак 3×3, сундук с
кнопками, печь, креатив на каждой вкладке, поиск по `#свет`, пресеты, редактор,
мир, подсказки у четырёх краёв экрана, расширенная подсказка, протяжка с
будущими числами, превью с бронёй и тремя статусами, значки эффектов в игре,
лист новых иконок.

## Автопилот

Настоящими клавишами и кнопками: E — окно открылось; протяжка ЛКМ делит стопку;
клик по рецепту в книге и Shift-сборка; верстак — сетка 3×3; креатив — поиск
`#свет` находит факел; Shift+3 и Ctrl+3 сохраняют и загружают пресет;
ползунок времени двигает солнце; F3+H включает расширенные подсказки, а F3 после
сочетания не открывает отладку.

# Что НЕ делается

- Варка зелий, стол зачарования, наковальня, редкость предметов.
- Открытие рецептов (все рецепты видны сразу).
- Раскладка окон в JSON.
- Логические блоки (рычаг, провод и т. п.).
- Щит, лук, снаряды.
- Управление геймпадом.
- Добыча в сундуках построек.
- Система локализации: имена только русские, id — латиницей.

# Риски

| Риск | Смягчение |
|---|---|
| Рефакторинг `ItemStack` задевает ~25 файлов | Первым шагом плана A, компиляция и полный набор тестов после каждого шага |
| Потеря предметов при миграции | Тест на байтах старого писателя, заглушки `missing`, `CheckSaves` по всем мирам |
| Пакетный рендер меняет картинку | Попиксельное сравнение кадров старого и нового рендера |
| Конфликты ввода (цифры, Shift/Ctrl, набор текста) | Правила записаны в D2–D3 и A6, покрыты тестами через `UiInput` |
| Сгенерированная графика не в стиле | Доводка к правилам дома, контрольный лист, процедурные заглушки |
| `Game.java` (4800 строк) растёт | Новое — отдельными классами (`GameWindows`, `PickBlock`, `DamageModel`, `PlayerPreview`); `Game` только связывает |
